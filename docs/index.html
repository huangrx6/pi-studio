(02) — 设计原则

Pi Studio 不是一个聊天窗口。
它把 Pi 的工作方式搬进桌面——会话留在本地，密钥留在本地， 技能、扩展与 MCP 也留在本地。窗口只是让这些原本在终端里的东西，顺手一点。

(03) — 能力清单

一个窗口，装下整个 Pi 生态。

不是把 CLI 套个壳——工作区、模型目录、技能、扩展与 MCP 都有对应的原生界面，改动直接写回 Pi 的配置文件。

01 / SESSION

流式会话

基于 Pi SessionManager 的流式对话、思维链展开与工具轨迹，重启后从 JSONL 完整恢复。

02 / WORKSPACE

多工作区

侧栏切换工作区，右栏文件树与文本预览，随时查看项目里的真实文件。

03 / MODELS

模型与提供方

本地 Pi 目录驱动的模型选择器；编辑 API Key，添加兼容提供方与自定义模型元数据。

04 / SKILLS

技能

读取全局与项目级 skills，分组展示；新增与移除都走 Pi 的文件约定。

05 / EXTENSIONS

扩展

列出 settings.json 包与 extensions-data，支持 npm / git 包源的安装与卸载。

06 / MCP

MCP 服务器

可视化读写 mcp.json，添加 stdio / HTTP 服务器，并单独启停。

07 / QUEUE

消息队列

运行中继续输入，排队发送；队列内容可编辑、可撤回，不会打断当前回合。

08 / PLAN

计划面板

把 pi-todo 适配为原生会话计划，任务状态跟随工具调用实时更新。

09 / DETAILS

主题与细节

亮暗双主题、圆角层级、字号与滚动条——都为长时间对话打磨过。

(04) — 工作流

从提问到改动，一条闭环。

没有多余的登录、同步或云端确认。打开工作区，说完话，看它执行，审阅改动。

01

选择工作区

指向磁盘上的一个目录，Pi 从这里读取项目上下文。

02

描述任务

自然语言、/ 命令、@ 文件与附件，一次说清。

03

观察执行

工具调用、代码 diff 与思考过程逐条展开，随时可中断。

04

审阅改动

文件预览与变更摘要留在会话里，回滚或继续都有据可查。

(07) — 数据

没有云端，
只有 ~/.pi/agent

Pi Studio 有意与本地 Pi agent 目录共享数据。桌面端改的配置，pi CLI 立即可见，反之亦然。

DeepSeek Harness 只贡献了视觉令牌与样式；没有 DSH Host、插件运行时、会话持久化或工作区注册表。

~/.pi/agent/
├── sessions      # 会话 JSONL · 唯一事实来源
├── auth.json     # API Key
├── models.json   # 提供方与模型目录
├── mcp.json      # MCP 服务器
├── skills        # 技能
└── extensions    # 扩展
(08) — 开发

本地构建。

需要 Node.js ≥ 20 与 pnpm。克隆仓库后按顺序执行即可。

$pnpm install安装依赖
$pnpm devVite + Electron 热更新
$pnpm test29 项单元测试
$pnpm run build && pnpm start生产模式运行
$pnpm dist打包 arm64 + x64 DMG
