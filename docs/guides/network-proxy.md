# 网络代理

入口：**设置 → 数据与应用 → 网络代理**。设置对所有工作区生效，保存在 Studio SQLite 的 `studio.network.proxy`，不会修改操作系统代理或其他应用的配置。

- **跟随系统（默认）**：由 Electron / Chromium 读取操作系统代理和 PAC 规则。页面显示访问 Google 连通性检测地址时系统实际选择的线路；PAC 可对不同地址选择不同线路。点击“重新识别”可刷新识别结果。没有配置系统代理时直接连接，不扫描本机端口，也不猜测代理软件的安装位置。
- **手动配置**：输入 HTTP、HTTPS 或 SOCKS5 代理地址，例如 `http://127.0.0.1:7897`。可以使用识别到的系统代理地址；地址不支持用户名、密码、路径或查询参数。需要认证的远程代理可通过本机代理软件提供无需认证的本机入口。
- **直接连接**：不使用代理。

手动模式可以填写不使用代理的域名或 IP 规则，以逗号分隔，例如 `*.local, 192.168.0.0/16`。本机回环地址始终绕过手动代理，便于访问本地模型服务。

“测试连接”使用当前表单中的配置访问 `https://www.google.com/generate_204`，不保存设置、不发送模型密钥或聊天内容，不调用付费模型。结果展示实际线路、HTTP 状态及耗时；收到非成功状态不等于网络连接超时。检查最多等待 15 秒。

保存后，后续请求采用新配置，无需重启。已经开始的流式回复继续使用原连接。未保存的表单更改在离开页面时提供丢弃确认。

## 请求覆盖范围

主进程在启动模型运行时之前统一安装 `fetch` 传输。Pi AI 使用默认 `fetch` 的模型 HTTP 请求、OAuth、模型目录、额度查询、技能与扩展下载均使用此设置。传输使用独立的内存 Chromium session，不与网页共享 Cookies，保持请求的取消信号、请求体和流式响应。

每种代理配置有独立的 session 和连接池。准备新 session 成功并持久化后才切换默认传输；失败时保留上一份配置。复用同一配置的 session 不会重复创建连接池，也不通过关闭所有连接来中断运行中的请求。

终端或子进程、内嵌及外部浏览器、更新器，以及自行使用 Node `http` / `https`、WebSocket 或其他独立传输的 SDK，不受这一 `fetch` 设置控制。例如 Bedrock / Vertex 的原生 SDK 和 Codex 的 WebSocket 路径仍使用各自的网络配置。此设置不会改变 TLS 证书验证。

## 排查连接超时

`UND_ERR_CONNECT_TIMEOUT` 表示尚未建立连接，不能据此判断套餐额度或密钥失效。先在代理页面识别系统代理，再测试连接。如果浏览器可访问而旧版 Studio 的模型请求超时，确认已运行带此网络设置的版本；旧版 Node 默认 `fetch` 不读取操作系统代理。

验证命令：`pnpm run qa:network`。检查使用 `.qa/network-settings/` 中的隔离数据和本机模拟模型，覆盖代理路由、流式响应、取消、保存与重启。需要额外验证 Google 连通性检测地址时使用 `PI_STUDIO_QA_NETWORK_LIVE=1 pnpm run qa:network`，仍不发送凭据或调用模型。
