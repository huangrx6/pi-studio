# Pi Studio 整体优化重构路线图

> 目标：在保留 Pi Durable 执行边界、Studio 数据边界和现有安全模型的前提下，降低理解成本，提升会话效率、视觉舒适度、响应速度与长期可维护性。
>
> 基线：2026-11-05。当前 `pnpm test` 通过 600 项，`pnpm run build` 通过；生产构建存在约 1.3 MB JavaScript 与 484 KB CSS 的拆分机会。

## 全局视觉验收规范（用户最新约束）

**简洁、大气、克制、有质感。** 此规范优先于后续任务中的候选设计，适用于所有 Agent 的新增和重构界面。

- 只保留当前路径的核心必要操作；同一信息和动作只保留一个主要展示位置，不叠加重复文案、摘要、提示或装饰。
- 采用舒展且统一的排版、间距、字号和对齐；用层级和留白组织内容，减少卡片嵌套、边框、徽标与阴影。
- 动效只用于必要的状态反馈和空间变化；不增加通用悬浮上移、浮起、弹跳或装饰动画，保留减动效支持。
- 输入区是主角：欢迎区使用纯标题，缺少配置时才出现配置动作；仅在输入为空时展示三个轻量文字示例，不增加示例卡、最近会话卡或重复欢迎说明。
- Composer 工具栏保留“更多”图标及其可访问名称与提示，不增加冗余“动作”等常驻文字；权限和模型说明优先放进现有选择器或按需提示。
- 右侧工作台入口使用轻量列表，不做多列装饰卡片；清晰的可点击区域和键盘焦点仍须保留。
- 检查每一处新增元素是否帮助用户完成当前任务；若只是填满空白、重复已有信息或增强装饰感，应移除。

## 使用方式

- 每项任务都要满足“改动范围 + 验收标准”后才算完成。
- P0 先解决首次使用、核心输入、导航和空间分配；P1 解决高频工作流和一致性；P2 处理扩展能力、重构和长期质量。前两批覆盖首页引导、Composer 展示抽离、设置导航、右栏宽度、阅读尺度、通用设置精简与低频设置按需加载；第三批完成精准会话查找、轨迹按需渲染和键盘焦点；第四批推进长期目标状态、错误层级与通知恢复；第五批完成模型选择竞态保护、扩展列表精简和长历史切换修复；第六批完成大侧栏窗口挂载、时间更新隔离和导航草稿保护；第七批完成模型、MCP、已安装技能的轻量列表与失败恢复；第八批完成权限、Harness 与工具配置的分区精简、草稿保护和跨页保存恢复；第九批完成子智能体、使用量与设置离页保护；第十批完成输入准备、异步附件、建议菜单与共享浮层键盘行为；第十一批完成归档找回、快捷键录制、上下文估算与已提交操作的只读刷新恢复；第十二批推进文件面板隔离、资源生命周期和真实 Electron 测量；第十三批修复终端尺寸回放并增加文件缓存预算；第十四批完成技能/扩展详情与服务切换保护；第十五批精简维护页面，隔离更新与 MCP 详情的异步状态；第十六批精简资源编辑与扩展安装，保护草稿、重复提交及成功写入后的只读恢复；第十七批补齐主进程内部提交/刷新分界、安装收据与模型运行时发布顺序（验收见各轮记录）。更大的 Epic 保持未完成。
- 涉及设置、权限、扩展、MCP 或凭据时，继续遵守 `AGENTS.md` 的安全边界：凭据只留在主进程，Renderer 只接收 JSON-safe DTO，扩展 UI 保持声明式。
- 每个阶段完成后运行窄检查，再运行完整门禁：`pnpm run extension:schema`、`pnpm test`、`pnpm run build`、`git diff --check`。

## 状态和分工

- `[ ]`：任务仍有未完成验收；`[x]`：实施、检查和集成验收全部完成。
- 状态使用“待实施 / 实施中 / 部分交付 / 待验证 / 已完成”；部分交付须写明已验收范围与剩余项，不能据此关闭整个 Epic。
- 负责人是当前分工建议，未启动项的 Agent 表示后续归属，不代表已派发。
- `/root`：主应用、通用设置、Composer、集成与验收；`/root/settings_nav`：设置导航、公共页头与旧样式清理；`/root/visual_foundation`：视觉、右栏与桌面 QA；`/root/roadmap`：任务清单、按需加载与失败恢复、菜单焦点、通知组件、隔离性能基线与窗口状态修复。
- 依赖 ID 表示先后关系；“无”表示可独立推进，所有源码任务仍依赖现有测试与安全边界。

## 现有能力，继续保留并测量

当前已有 transcript 回合窗口挂载、会话缓存、流式按帧合并、错误清洗、减动效规则和右面板宽度记忆。这些能力的任务应是补测、修正边界或隔离更新，不是从零开发。窗口挂载不等于全程有界虚拟列表，读取完整历史与 DOM 挂载量应分开测量。

已观察到的约 1.3 MB JS / 484 KB CSS 是某次构建体积，不代表启动时间或卡顿程度。先建立可复现的性能基线，再决定拆包和调度策略。

- **问题**：工具调用、模型失败、连接失败和长任务暂停时，用户不一定知道发生了什么或下一步做什么。
- **改动**：基于已有 `errorText` 错误清洗统一错误信息的层级：简明原因、必要恢复动作和可展开技术详情，避免四个重复小标题或嵌套卡片；运行时保留一个主要阶段状态和停止入口；错误通知可跳转到对应会话。
- **验收**：网络失败、权限等待、MCP 断连、模型无响应、压缩失败各有可操作恢复路径；技术错误不会泄漏凭据。
- **风险/依赖**：需要复用现有 `errorText`、通知中心和权限确认组件。

## P1：高频工作流效率

### P1-UX-01 侧栏会话管理

- [ ] **状态：部分交付（详见第三轮记录）；负责人：`/root`；依赖：P0-UX-03。**

- **问题**：长时间使用后工作区和会话列表难以扫描，运行、未读、失败、置顶状态不够突出。

- **验收**：100+ 会话仍能通过搜索、筛选和排序在 3 次操作内找到目标；切换工作区不改变当前会话草稿。
- **风险/依赖**：需保持 SQLite 投影、拖拽排序和归档恢复一致。

### P1-UX-02 对话回答层级

- [ ] **状态：部分交付（详见第三轮记录）；负责人：`/root`；依赖：P0-UX-05。**

- **问题**：工具轨迹、思考、回答和代码改动在长会话中容易混在一起。
- **改动**：优化回答与工具轨迹的主次关系；原始参数和结果按需展开；只对可证实且尚未清楚展示的改动/验证提供紧凑入口，不强制每轮增加结论、依据、改动、验证四块卡片，不重复回答已有摘要。
- **验收**：短回答保持紧凑；长回答仍能快速找到最终结论、错误位置和改动文件；展开状态遵守用户偏好。
- **风险/依赖**：不得破坏 transcript 窗口加载、请求轨迹和文件差异配对。

### P1-UX-03 长任务进度和恢复

- [ ] **状态：部分交付（详见第四轮记录）；负责人：`/root`；依赖：P0-UX-05。**

- **问题**：长期目标、子智能体和排队消息的状态分散在多个区域。
- **改动**：为当前任务保留一个主要状态位置，按实际状态显示必要的阶段、队列或暂停原因；子任务详情按需展开，完成结果沿用已有回答，避免再加一份摘要。不编造完成百分比或剩余时间 ETA。
- **验收**：运行、暂停、阻塞、恢复、完成、失败六种状态都有可解释文案和可操作按钮；切换会话后状态不丢失。
- **风险/依赖**：继续由 Durable 作为任务事实源，Studio 只保存投影。

### P1-UX-04 权限和模型透明度

- [ ] **状态：部分交付（第五轮模型范围与不可用原因、第八轮权限作用域与草稿预览已覆盖；上下文与真实执行路径仍待完整验收）；负责人：`/root`；依赖：P0-UX-02。**

- **问题**：当前模型、供应商、思考强度、权限范围和上下文用量分散。
- **改动**：在现有 Composer 控件中提供唯一的模型/权限入口；作用域、能力、上下文上限和风险解释放进相应选择器或详情；不在会话头部复制同一份执行摘要。
- **验收**：用户能在不打开设置的情况下回答“当前使用哪个模型、会修改哪里、上下文剩多少”。
- **风险/依赖**：不得把凭据或 Durable handle 送入 Renderer。

### P1-UX-05 通知与撤销

- [ ] **状态：部分交付（第四轮完成来源归属与归并，第三十八轮增加误归档撤销，第四十轮收敛长错误展示）；负责人：`/root`；依赖：P0-UX-05。**

- **问题**：通知只有数量提示，完成、失败、等待授权和更新提示的优先级不够清晰。
- **改动**：按会话归类通知，区分成功、注意、失败、等待；只为确实有恢复机制的操作（例如归档）提供撤销；永久删除会话、丢弃 worktree 不承诺撤销，应准确展示影响并确认。
- **验收**：用户可从通知直接回到来源会话；重复通知合并；永久删除仍按产品确认策略执行。
- **风险/依赖**：撤销必须对应真实恢复操作；不得恢复仅有 UI 投影而底层已经永久删除的数据。

## P1：性能和工程质量

### P1-PERF-01 首屏代码拆分

- [ ] **状态：部分交付（详见第二轮记录）；负责人：`/root`；依赖：P1-OBS-01。**

- **问题**：当前生产 Renderer 主包约 1.3 MB，CSS 约 484 KB。
- **改动**：先测冷启动、首次可输入时间、模块解析与首屏渲染；按证据对设置页、模型对比、子智能体、技能中心或重型插件按需加载。仅在模块图和测量支持时采用 `manualChunks`。
- **验收**：首次打开主会话不加载未使用的设置/扩展代码；主包体积和首屏加载指标有基线对比；所有路由仍可离线打开。
- **风险/依赖**：需要处理动态导入失败、加载占位和错误恢复。

### P1-PERF-02 渲染更新边界

- [ ] **状态：部分交付（轨迹按需渲染、第五轮历史切换与第六轮侧栏窗口/计时隔离已交付；Profiler 与其他区域更新边界仍待覆盖）；负责人：`/root`、`/root/roadmap`；依赖：P1-OBS-01。**

- **问题**：App 根组件持有大量状态，部分状态更新可能触发无关区域重渲染。
