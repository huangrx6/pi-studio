# 知识库规范

文件留在同一个 notes 目录。本规范适用于人工整理及 AI 写入。沿用库里已有的目录名。

| 分类 | 收什么 |
| --- | --- |
| 00 Inbox | 尚未归类的想法、剪藏和临时笔记 |
| 01 Projects | 有清楚目标、交付物或结束日期的项目。保留进度、决策和会议记录 |
| 02 Areas | 持续负责的领域。保留标准、例行操作与长期职责 |
| 03 Resources | 可以跨项目复用的知识、案例和学习笔记。按主题整理 |
| 04 Archive | 已结束或目前无须维护的项目和领域 |
| 90 Assets | 图片、PDF 等附件。新增附件可按年份和月份组织 |
| 99 System | 本规范、模板、索引与整理约定 |

## 项目如何沉淀

项目记录保留决定、当时的背景和结果。可复用的结论整理成 Resources 下的主题笔记，在原记录里链接过去。有同主题笔记时优先补充已有笔记。来源不明确时，先记录待确认项。

## 文件、属性和链接

- 资源笔记用清楚的主题名。会议或日志用 日期-标题 命名。
- 新 Markdown 可包含 title、created、updated、tags。项目需要时加 status，取 active 或 done。
- 支持 [[笔记名]]、带目录的 Wiki 链接和标准 Markdown 相对链接。重名时写全相对路径。
- 需要手写导航时使用 _index.md。附件用相对路径链接。
- Markdown 适合编辑和检索。HTML 适合需要独立排版的阅读稿，使用本地样式与附件。

## 整理周期

定期看 Inbox，把已确定归属的内容移到对应分类。项目结束时，将完整项目目录移到 Archive，再提炼可复用的结论。移动前检查引用，保持链接有效。
